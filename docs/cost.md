# 成本：把单价从"不敢想"压到"可以日常跑"

## 1. 成本定律

**成本 ≈ 请求数 × 平均上下文长度。**（实测：输出 token 只占约 1.5%；平均每次请求上下文 80–110k tokens。）

推论，全部经实测验证：

- **同质项目成群处理最省**——一个片一次读完，请求数/项 越低越省（463 项一片：请求/项 0.14）；
- **反复调工具最贵**——每轮搜索/抓取都把上下文再撑大一截；
- **多写字段、多附证据几乎免费**（输出便宜），贵的是"上网核实的轮数"。

## 2. 单价表（实测，tokens/项）

| 打法 | 单价 | 说明 |
|---|---|---|
| 机械层 | **0** | 不调模型，全库可跑 |
| 标题/文件名浅扫 | **3.5k–5.1k** | 4,000 项实测；只给标题+文件名+已知作者表，不上网 |
| 同质大户片（约 460 项） | **13.4k** | 甜点区 |
| 中等片（约 285 项） | 29.2k | 854 项三片实测 |
| 小片（约 105 项） | 59k | 请求/项 翻倍 |
| 发现型小块（50 项） | 62k–188k | 最贵：没有可共享的新实体，全靠当场搜 |

另测：**完全无本地线索的孤立项 160k/项**——这就是"先榨干本地、实体先行"的价值所在。

## 3. 最便宜的档位反而更贵（判死记录）

同一批内容用最低价的模型档位重跑两次：**空响应率 31–40%**，同期的主力档位只有 1–13%；两战两败、零产出。
"空响应" = 供应商返回"无文本、无工具调用、无用量"。失败重试的成本远超差价——**低价档位判死**。

## 4. "空响应墙"与片容量

- 空响应是供应商侧的持续背景现象（约每分钟 1–3 次）；片"活得越久"（请求数/时长越高）越容易撞上连续空响应。
- 实测：150 项的长片被打死、零产出（4.65M tokens 白花）；拆成 3×50 后 3/3 成功。
- **定稿容量：发现型 ≤50 项/片；同质深扫 ≤1,000 项/片**（2,000 项/片时 6 个片死 3 个）。
- 兜底：每批追写落盘——即使被打死，已产出的部分能保住。
- 失败处理：**不中途换对话重试**；等整批跑完，统一拆小重跑。

## 5. 策略顺序本身就是 22 倍杠杆

同一个全库：

- 先做便宜的浅扫（≈70M tokens 投影），再对缺口做深波；
- 对比：直接上发现型全跑（≈1,539M 投影）。

→ **便宜的先跑，贵的只跑缺口。** 顺序就是成本。

## 6. 免费通道

- 机械层零成本（全库一遍）；
- 字段继承：同作品组内已补字段免费复制（已兑现 2,400+ 条事实）；
- 缓存：24 小时内抓过的页面直接读，不占新的抓取预算。

## 7. 排程方法

- 把额度当**日预算**：剩余额度 ÷ 上一波实测单价 ≈ 还能跑几波；
- 每波记录实际花费，形成自己的单价表，再排下一波；
- 额度见底就等窗口重置，不硬撞。
