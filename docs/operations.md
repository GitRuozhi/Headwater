# 运营：每天怎么开、怎么收

## 1. 波次结构

- 一"波" = 一次批量派发；"片" = 交给一个子代理的同质项目组；
- 并发有上限（参考实现是 3）——满了就排队，别硬挤；
- **每跑一小波（1–2 批）停下整理攻略与教训**，再继续；"全跑完才整理"会让系统性错误滚雪球。

## 2. 额度与排程

- 按日窗口估算：剩余额度 ÷ 上一波实测单价 ≈ 可跑波数；每波前后各记一次账；
- 额度见底就等窗口重置；
- 花费台账决定下一波的容量设计（单价变了，片的大小就要变）。

## 3. 缓存纪律

- 抓过的页面 24 小时内复用，不算新的抓取；
- 为某个项目抓的页面打上项目标记，以后能机械回填/审计；
- 大页面先扫关键词再精读。

## 4. 批前 / 批后

**批前**（材料包自检）：候选已分级？已知实体已带上？攻略已注入？包已瘦身？

**批后**（固定五件事）：

1. 两层收件（判断件 + 漫游件各入一次）；
2. 跑继承（同作品组内传播；幂等，可重复跑）；
3. 冲突导出成核对队列；
4. 机械提取（页面上的结构化信息由脚本从缓存提取，不由模型转录——见 [contracts.md](contracts.md)）；
5. 更新攻略库：**走通的、走不通的、部分走通的都记**（失败也是资产）。

## 5. 幂等与回退

- 继承、机械提取可重复跑（幂等）；
- 修正留旧值；主名变更自动降级旧主名；
- 收件器对值有守卫：非人名形态（规格串/日期/来源标记/分类词）不建实体，坏值不污染台账。

## 6. 子代理的运行验证

平台可能"回执说 A 模型、实际跑 B 模型"——真实发生过，一次事故烧掉数百万 tokens 且记错账户。

→ 每次派发后**验证子代理的实际模型路由**；发现回退立即停；会话模型切换前后不要派批。

## 7. 内容与合规自律

- 不下载作品；只抓公开页面与元数据；
- 限量、慢速；被拦截先降速/冷却/换路（换出口节点），**不把站点判死**；
- 截图与缓存只进专用目录，不随仓库分发。
