# 方法：一条链，把"溯源"做成批量化流水线

本文是整套方法的完整说明。原则都来自一个 19,877 项真实收藏库的实操，包括大量失败后的修正。

## 1. 问题定义：二次创作在流传里丢什么

一件二创作品从作者手里到观众眼前，通常经过：发布 → 转存 → 搬运 → 打包 → 改名/重压。
每一步都可能丢信息：

- **署名**（作者是谁）——最常丢、最难找；
- **原作**（角色/作品所属的 IP）——标题里可能只剩角色名或一个梗；
- **系列与集号**——合集打包后顺序和归属断裂；
- **出处链接**——原帖失效、作者改名或销号；
- **标签与内容属性**——页面上最全的一类信息，在文件里只剩一个文件名。

溯源 = 把这些字段找回来，并留下证据。

## 2. 三层设计（外加一层"判停"）

| 层 | 做什么 | 成本 |
|---|---|---|
| 机械层 | 本地信号榨干：目录与分类名、文件名模式、描述里的链接、视频元信息、同一内容的重复分组 | 零（不调模型） |
| 判断层（文本 + 在线合并） | 子代理读材料做判断 + 按"攻略库"上网核实，一条链跑完 | 主要成本 |
| 视觉层 | **判停**：成人内容会被模型拒审且毒化会话；非成人内容收益也低 | — |

视觉判停的理由见 [lessons.md](lessons.md)——这是一次严肃评估后的决定，不是偷懒。

## 3. 一条链（合并跑）

一个"片"（一组同质项目）交给一个子代理，固定流程：

1. 读材料包（本地信号 + 已知实体 + 攻略）；
2. **先产出判断件并落盘**（防丢）；
3. 判断有没有"必须上网"的缺口；
4. 有，就按攻略库漫游（搜索 → 主页 → 作品页/百科页）；
5. 产出漫游件（实体档案 + 主页 + 出处 + 修正）；
6. 收件：两层各入库一次。

工程约束：

- **先落盘再漫游**——任何一步死掉，产出不丢；
- **每批落盘/追写**——长任务随时可能被供应商的"空响应墙"打断（见 [cost.md](cost.md)）；
- 片容量有上限（同上）。

## 4. 材料包：把"该知道的"一次给全

- **先榨干本地，再上网**：目录名、文件名、描述、元信息、重复分组都能免费提供线索；
- **候选分级**：真名 / 噪音词（规格、分辨率、日期、分类词）/ 角色名（角色名不是作者）；
- **已知实体与别名随包下发**：跨批去重，同一个作者不重复搜；
- **人类判别法随包注入**（见 [quality.md](quality.md)）——一条规则、全批次生效；
- **包要瘦身**：路径缩成文件名、重复线索去重、空字段裁掉（实测省三成以上，语义不变）。

## 5. 库是共享中介

作者/原作是**全库共享的实体**：主页、别名、介绍只查一次，后续批次的材料包直接带上。
"跨批去重靠库"是把批量成本压下来的结构性原因——台账越厚，新批次越便宜。

## 6. 重复检测 = 免费证据

同一件作品的多个副本（含跨分辨率重传）被精确分组（875 组 / 1,851 项）：

- 组内 = 同一件作品的**硬证据**；
- 已补成员的字段**免费继承**给未补成员（只填空、不覆盖、留痕）；
- 同组不同来源的字段互相印证，冲突自动浮出，转成核对队列。

## 7. 机械与判断的边界（硬准则）

- 机械只做**高精度、无歧义**的事：格式规范化、大小写/变体合并、非人名形态过滤
  （规格串、日期、纯数字、来源标记）。
- **有歧义的一律不上机械**——三条路：在线核实、人类清单、留空。
- 原因：连人类的误判率都不低；机械只配做"错了也只是格式错"的事。**误删比缺省贵。**

## 8. 证据纪律

- 每个非空字段必须附一句依据（引材料原文或页面原文）——硬要求；
- 页面没写的不许编，查不到就留空；
- **负结论要带条件**（在哪些平台、用什么手段查过），并在能力升级后复验；
- 修正走专用通道：改值留旧值，可追溯。

## 9. 可移植性

方法只依赖三样东西：

1. 一个父 Agent 能派发子代理（fan-out）；
2. 子代理能读本地材料、写本地文件、上网；
3. 一个本地库做共享中介（任何 SQLite/JSON 存储都行）。

参考实现使用一个支持子代理动态工作流的 Agent 平台（ZCode），但方法本身不依赖它。
子代理用便宜快速的模型可行——但有代价（空响应率上升，见 [cost.md](cost.md)）；
本地部署模型理论可行（未实测，如实标注）。
