# 质量：怎么保证"找回来的是真的"

## 1. 先说清楚：作品归属本就多义

同一作者换名、在不同平台用不同名字、联合作者、表/里版本、二改与转载……"谁做的"经常没有唯一答案。
因此我们**不测错误率**（测了意义也不大）——改用三件套：**证据纪律、冲突分类、人类清单**。

## 2. 人类判别法（这套系统的独特资产）

模型的知识里没有、但老观众一眼能看出的"黑话"，靠人类逐条提供；一条注入，全批次自动生效：

| 形态 | 含义 | 处置 |
|---|---|---|
| 写作内容/口味标记的词（如 SEX、NTR 这类场景词） | 作者手打的引流/内容标记，常被塞进"作者位" | 进标签，不是作者 |
| 「定制 XX」 | 观众委托定制 + 内容词 | 拆成两个标签 |
| 「表」/「里」 | SFW / NSFW 版本标记，常成对出现 | 不是作者；版本对可建立关系 |
| 来源站前缀（"某站原档"式命名） | 从来源站直接下载、文件名未改（文件名因此可信） | 记"原档"标记，作者留空 |
| 纯数字名 | 可能是搬运号或站点 ID，**也可能是真作者名** | 不机械删；查证 |
| 与上传者昵称相近／全网查无／横跨多个作者的作品出现 | 疑似搬运号自封名 | 宁空勿错，进人工清单 |
| 模型标记（如"XX 式"） | 表示用了某人的模型/素材，不代表是他做的 | 进标签；作者另找证据 |

规律：**判别法是分站的、逐条累加的、永远不完整**——拿到一条加一条；没给的一律留空或标存疑，不猜。

## 3. 署名冲突的六类成因

① 同一作者的别名；② 联合作者；③ 表/里或 remix 版本对；④ 标记词被误当作者；
⑤ 同主题潮流被误当同一系列；⑥ 真冲突（需在线核实）。

归口：能机械合的直接合；**带编号/后缀的变体留给在线核实**；在线也定不了的才进人类清单。

## 4. 机械与判断的边界

机械只做高精度无歧义的事（格式、变体合并、非人名过滤）；有歧义的上在线/人类/留空。

两个反例（都造成过实际损失）：

- 一个"看起来像乱码"的名字，经人工确认是**真作者名**；
- 一条"太短的一定是噪声"的清理规则，误删了真实的短名。

→ **误删比缺省贵。** 系统默认"留空/存疑"，从不默认"删掉"。

## 5. 负结论会过期

早期（能力不足时期）得出的"找不到"必须复验。实际复验中：两条被推翻、一条升级为带考证的"查而判无"。
负结论记录时必须附条件（时间、平台、手段），能力升级后挑最可疑的重查。

## 6. 修正与留痕

- 每个值带来源层级（机械/文本/在线/继承/修正），多来源自动累积；
- 修正不改历史：旧值留痕、新值入库；主名变更时旧主名自动降级；
- 默认给"最可能的值"；低可信值"查得到"就够——不为"永不错"过度投入。
