# 教训：判死的路与踩过的坑

本文是负面知识库——比"什么能用"更值钱的是"什么试过了不能用"。

## 1. 判死的路（别再投入）

- **视觉级**：让模型"看"内容抽信息——成人内容会被拒审，且一张问题图会**毒化整个会话**；
  非成人内容收益也低。整体判停。
- **最便宜的模型档位**：两战两败（空响应 31–40% vs 主力档 1–13%）。
- **纯文本单独成遍**：文本判断与在线核实分开跑 = 同一材料读两遍；合并成一条链后成本显著下降。
- **长任务碎片化重试**：长片被打断后"立刻换个对话接着跑"浪费严重；正确做法 = 整批跑完、统一拆小重跑。

## 2. 事故与修复

| 事故 | 根因 | 修复 |
|---|---|---|
| 60 个系列静默丢失 | 输出契约字段名与收件器不一致，且无告警 | 收件器兼容两种键名 + 契约回归测试 |
| 数百万 tokens 记错账户 | 平台静默回退子代理模型 | 每次派发后验证实际模型路由 |
| 53 项误归属 | 3 字符的别名撞上了一个角色名 | 别名参与匹配需要 ≥4 字符 |
| 真作者名被清理误删 | "太短 = 噪声"规则一刀切 | 规则窄化；误删比缺省贵 |

## 3. 正面案例（一次机械扫描省下整批模型钱）

标题/文件名里的标记词（内容/口味/来源类词）做**机械扫描**，一次成批打标 1,367 项——零模型成本。
这类词几乎不出现在"作者位"，机械扫描即可，不需要动用子代理。

## 4. 工程坑

- 脚本能自包含就自包含：清单内联，别依赖外部文件（曾首跑即挂）；
- 同一环境里两种路径解析规则（按仓库根 vs 按工作目录）——**一律写绝对路径**；
- 子代理"同名重开"会被平台判死：一个子代理身份在循环外建好再复用；
- 长脚本里的引号/转义是高频事故源：**写文件，而不是拼命令行**。

## 5. 原则（血的教训压缩版）

- 负结论必须带条件；能力升级后复验；
- "匹配上了"不等于"是对的"：中签率 ≠ 质量；
- 被反爬拦截先换路（换出口/降速/冷却/读缓存），**不把站点判死**；
- 站点可用性会漂移：一切以最近一次实测为准。
