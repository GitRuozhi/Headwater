# headwater

**你刷到的每个二创作品，作者是谁？原作是什么？**

多数人的答案是"不知道"——不是不在意，是溯源太麻烦。一件作品从作者发布到你的屏幕上，会经过转存、搬运、
打包、改名，署名在一轮轮流传里一点点丢干净。而人们习惯刷到啥看啥，很少去翻原出处——这份"没人愿意做的活儿"，
现在可以交给 AI。

**headwater（水源、上游）让 AI 替人把溯源做完：批量找回作品丢失的作者、原作、系列、角色、出处。**

这不是构想，已经跑出一个完整实例：一个 **19,877 项的真实收藏库，72% 的作品被 AI 找回了信息**。
人类全程只做两件事：教它判别规则、审最终清单。

> 本仓库只提供方法，不提供内容——不含任何作品、素材或下载方式。

## 为什么值得做

- **看的人多，查的人少。** 二创的观众数以亿计，愿意逐个翻原出处的人寥寥无几。但"这是谁做的、原作是什么"
  的需求一直都在——只是以前没人愿意替你做这项苦工。
- **网站也需要。** 同一件作品在多个站之间流转：有的搬运站整理得比原创站还全，而原创站缺乏改进数据的动力。
  一份可靠的溯源数据，对站点本身同样有价值。
- **以前不可行。** 人肉溯源一天只能做几十项，成本高到没人干。AI 把这件事的成本打下来之后，
  它第一次变得普遍可行：一条流水线一天能扫上万项。

## 它凭什么能做对

- **人类给规则。** 老观众一眼能看懂的门道——哪些词其实是内容标签、哪些像名字的东西其实是搬运号自留名、
  "表/里"是什么意思——人类提供一条，AI 之后全批次照办。
- **AI 干批量活。** 读材料、做判断、上网核实、把每个结论连证据一起入库，全部流水线化。
- **纪律兜底。** 页面没写的不许编，查不到就留空；上网限量、慢速、优先用缓存；同一件作品的不同副本互相印证。

## 现状与路线图

- **定位：AI 的能力增强，早期开发中。** 目前完成的是 Wallpaper Engine（动态壁纸）一个领域的实例，
  处理文本类信息为主；完整产品在规划中。
- 路线图：更多领域（不止壁纸）、更多信息维度（画面、音乐、声优……）、更细的作者/原作关系网、更深的历史溯源。
- 方法不挑平台：任何支持"派发子代理"的 AI Agent 都能复用这套流程；用便宜快速的模型也能跑（有代价，见文档）。
- 本仓库先公开**方法**（中文；以后可能补英文）；配套工具未来从主项目迁移过来。
